# 草图转译规范（sketch → free-v1 请求）

角色：用户发来一张图（手绘草图 / 白板照片 / PPT 或 Excel 排版截图 /
**别家 BI 报告截图**「照这个感觉做」），模型把它转译成 `free-v1` 请求。
这是「画」模态的落地通道（`docs/free-authoring-discussion.md` §3.3）——零新代码，
本规范 + SKILL.md 指引就是全部实现。

## 1. 转译规则（图 → 请求）

| 图上元素 | 转译落点 |
|---|---|
| 顶部整行大框（标题+几行小字） | `cover`（标题进 title，小字进 meta/summary） |
| 一行 3–4 个小框（框里一个数字+短语） | `kpis`（每个小框 = 一张 KPI 卡；短语 = label，数字含义选 type/measure） |
| 大框（坐标轴/饼环/条块示意） | 一张 `chart`：形状→presetId（折线=line.trend、条=bar.rank、堆叠条=bar.stacked、饼=pie.share、环=donut.share、漏斗=funnel.stage、网格=table.aggregate、点群=scatter.correlation） |
| 框侧的下拉/按钮示意 | `filters`（每个控件 = 一列的交互谓词） |
| 成段文字框 | `insights`（≤3 条）或 sections 的 narrative |
| 框下小字注释 | 对应 chart 的 `annotation`（口径注释） |
| 框上写的时间范围（「近6期」「本月」等） | 报告级 `filters`（时间列用 `daterange`，**不要用 `in`**——时间值会被日期归一）；锚点缺省 = 数据最大期，草图写「今」类字样才用自然今天 |
| 行/列上标注的字段名 | `encoding.dimension / measures / breakdown`；可辨认就同时写 `columnRoles` |

## 2. 相对位置 → 网格坐标

草图只给相对位置，转译为 12 列网格的显式 `layout.x/y/w/h`（layout_solver 对
显式坐标原生支持——钉过的版面永不重排）：

- 整行元素 → `w:12`；左右并排 → `w:6+w:6`；左宽右窄 → `w:8+w:4`。
- 上下次序按草图中各块**底边出现的先后**排 `y`（同行的 y 相同）。
- 图表不写 `h`（编译按基数/内容定高），文本/KPI 写建议 h（KPI=2、文本段=3 起）。
- 只在草图明显表达了版面意图时才写坐标；草图只有块没有位置感 → 省略 layout，
  让 pack_layout 自动排（顺序仍按草图从上到下）。

## 3. 歧义缺省（拿不准就这么猜，并告知）

1. 顶部一排小框（≤5 个、无数值轴感）→ KPI 卡；只有一个 → 可能是 KPI 也可能是
   文本带，缺省 KPI。
2. 框内同时画了轴和数字标注 → 图表（数字是数据标签，不是 KPI）。
3. 认不出形状的框 → `table.aggregate`（聚合表永远成立）。
4. 草图字段名与数据列对不上 → 按语义找最接近的真实列并在回复里列出
   「草图字段 → 实际列」对照；找不到就省略该块，不硬造。
5. KPI > 4 张 → 只转译前 4 张并告知（KPI 条容量 4）。

**所有缺省决策写进回复的「转译说明」清单里，逐条可反驳。**

## 4. 红线：转译必出草案确认，不静默采信

草图是模糊的，误差要到实物上对齐：

1. 转译 → 生成 free-v1 请求 → **构建草案给用户看**（构建本就不强制审计；
   要更便宜可 `--audit-scope smoke`）。
2. 回复格式：转译说明（上面 §3 的清单）+ 草案路径 + 一句「对着报告说哪里不对，
   我改了重出」。
3. 用户反馈走增量补丁重构建（或编辑器就地拖），**不要每次都从草图重转**——
   草图只在第一轮起作用，之后以草案/报告为准（L3 看图说话闭环）。

## 5. 降级路径

- 部署环境无视觉能力（模型读不了图）→ 请用户改填诉求单的「排版偏好」槽
  （references/brief-template.md），用文字描述版面结构。
- 草图信息量不足以确定数据绑定（只有框没有任何字段/指标线索）→ 只转译
  版面骨架（块类型 + layout），数据绑定从表结构推断并在转译说明里标注
  「猜测项」。

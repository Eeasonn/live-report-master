# 报告诉求单（brief）— 用户诉求的结构化入口

角色：这是**模型的操作手册**。用户永远只面对三件事——说一句话 / 填诉求单 /
对着报告提修改；诉求单是「选」这种模态的载体（`docs/free-authoring-discussion.md` §3）。
本文件定义诉求单的固定槽位、缺省语义、以及「诉求单 → 构建路径」的映射规则。

## 1. 模板（v2 通用版，逐字给用户，或由访谈代填）

通用、领域中立：槽位对任何二维长表（事实明细 / 周期快照 / 日粒度流水）都成立；
微示例跨行业轮换，具体领域词汇只出现在用户的填写里。设计沿革与迁移对照见
仓库根 `docs/brief-template-v2-proposal.md`。

```markdown
# 报告诉求单
【怎么用】只填【A 必答】就能出稿；【B 选答】全部可空，空着 = 按数据画像自动推荐
（每个自动决策都记录在 build/decisions.md，可回滚）。答不出就留空，最多被追问 3 个带默认值的问题。

## A 必答
- 数据文件：路径（多张表就都列出，并说明靠哪两列互相关联，如「订单表.门店ID = 门店表.门店ID」；
  已交叉的宽矩阵请先融成「维度 + 数值」长表）
- 一行 = 什么：表粒度一句话（如「一行 = 一笔订单 / 一名员工某个月 / 某门店某一天的销售记录」）。
  答不确定可空着——构建前会先做数据画像讲给你听
- 要回答的问题：1–5 条，每条一行五要素「**维度 × 指标 × 时间窗 → 图**」
  （例：按门店 × 销售额（本月）→ 柱状；按月 × 投诉量（近 12 个月）→ 折线；
  不知道用什么图就空着让推荐来选；总览类问句直接指名 KPI 卡；时间窗不写 = 全量）

## B 选答
- 口径与派生：比率/得分写分子÷分母与单位（如 达成率 = 实际 ÷ 目标）；若原表自带比率列，
  注明「聚合后重算，不要对比率列取平均」；**单价/售价/价格列注明「仅同品类内可比——跨品类
  视角请用折扣率/价格带/分品类切片，不要跨品类平均」**；等价/冗余的维度只保留其一；数值单位（元或万元、件、人、%…）
- 对账锚点：1–3 个合计真值（如「全年销售额合计 = ___」），构建后自动抽查勾稽
- 对比方式：环比 / 同比 / 目标 / 无（不写 = 无）
- 时间分桶与锚点：趋势按日/周/月/季/年（不写 = 按数据密度自动选）；
  「本月/最新一期」以数据最大期为准，要按自然今天请写明
- 交付与受众：单文件离线 / 本机服务端打开；报告标题；给谁看（经营会投影 / 自用查数 / 发人手一份）
- 版式：页签或单页（页签怎么分组可写）；主题色（内置名 default/huawei/pop…，或指定品牌色参考）；
  页宽（1280/1440/1600/1920）；封面有无；也可贴一张草图或参考截图
- 正负清单：必须有 ___（如 KPI 卡、合计行）；不要出现 ___（如 散点图 / 明细表 / 地图 / 占比饼图）
- 分析动作：洞察批注挂哪张卡旁边；筛选器与默认值；TOP-K 的 N；下钻层级（如 地区→城市、品类→SKU）；
  维度取值要合并成组（如 一线/新一线城市）；**不需要的动作也写明**
- 刷新：是否定期更新数据；主键列 = ___（覆盖/追加更新用）；字段配置与版式是否继承上一版
```

规则（沿 v1）：**每一槽都有缺省（不填 = 数据形态推断），任何一槽都不强制**。填空永远
比自由写作容易——用户答不了的就留着，别追问到烦。

## 2. 槽位 → 请求词汇映射

| 槽位 | 落点（请求词汇见 authoring-feature-map.md） |
|---|---|
| 数据文件 | `--table` 入参；多表 = file 数组 UNION 或 relations（关联键声明） |
| 一行 = 什么 | DataProfile 核对；粒度决定可加性判断与比率合法性 |
| 要回答的问题（五要素） | 每条问句 → 一张 chart：维度→`dimensions`、指标→`measures`、时间窗→filters/分桶、图→`presetId`/`encoding`（空 = suggest 按问句动词选：趋势/对比/构成/转化/关联） |
| 口径与派生 | `derived.measures`（聚合级比率，重算不取平均）/ `derived.columns`；冗余维度只声明其一 + `columnRoles.ignore`；单位 → measureTypes（divisor/currency/percent） |
| 对账锚点 | 声明 `request.anchors:[{label?,measure,value,aggregation?}]`（≤8 条，measure 可引用计算列）——编译期对真实表重算勾稽，**不符即构建失败**（P2 已落地，2026-10-13）；实测值仍记入 build/decisions.md |
| 对比方式 | 无指标时 → 不落；有指标时 → 数据源配置建窗口派生指标 + `kpi.compareMeasure` |
| 时间分桶与锚点 | `dimensionBucket`（日/周/月/季/年）；「数据最大期」锚 = dataAsOf 口径 |
| 交付与受众 | 单文件 → `--mode singlefile`；本机服务端 → `--mode server`；受众 → 汇报模式建议 + 口径注释密度；标题 → cover |
| 版式 | `runtime.mode`（tabs/单页）、`style.chartTheme`、`pageWidth`、封面；草图/截图 → sketch-transcription.md 转译 layout |
| 正负清单 | **排除项是实现自由的关键**：不要明细 → 不写 `dataTable`；不要 KPI 条 → free 档；不要某类图 → charts 里不声明；「必须有」→ 显式声明 |
| 分析动作 | 批注 → `chart.annotation`/文本带；筛选 → `filters` / `dimScopes`；TOP-K → `topK`；下钻层级 → `hierarchy`；值合并成组 → `dimGroups` |
| 刷新 | upsert 主键列（覆盖/追加两模式）；`curation_inherit` 继承链 |

## 3. 诉求单 → 构建路径（三档）

1. **只填「要回答的问题」** → 标准模板（`--patch`，suggest 默认 + 补丁覆盖）。
   快速看数的缺省路径。
2. **填了排除项 / 点名了图或版面** → 仍是标准模板，但补丁里显式覆盖
   （排除 = 不声明 + 必要时 `columnRoles.ignore`）。
3. **声明了完整结构取舍**（明确不要封面 / 不要 KPI 条 / 只要某几块）→
   `--free`（templateId=free-v1，声明即全部，无自动填充）。

判断启发：**用户在「要什么」之外还说了「不要什么」且成体系**（比如一张极简
查数页），才走 free；否则标准模板的自动填充是增益不是噪音。

## 4. 诉求单的落盘与生命周期

- 诉求单落盘为 `build/brief.md`（与 `build/decisions.md` 并列）。
- 它是诉求的**累积状态**，不是一次性问卷：月度刷新 / 迭代修改时增量改它，
  再按 §3 重新选路径构建。
- 用户对草案报告说的每句修改（「趋势换占比」「KPI 换毛利率」），除转成补丁外，
  同步回写诉求单对应槽位——下次刷新不丢。
- 与 decisions.md 的分工：brief.md 记**用户要什么**（需求侧），
  decisions.md 记**系统/作者各定了什么**（供给侧）。交付时把 decisions.md
  指给业务，把 brief.md 留给下一次刷新。

# 报告诉求单（brief）— 用户诉求的结构化入口

角色：这是**模型的操作手册**。用户永远只面对三件事——说一句话 / 填诉求单 /
对着报告提修改；诉求单是「选」这种模态的载体（`docs/free-authoring-discussion.md` §3）。
本文件定义诉求单的固定槽位、缺省语义、以及「诉求单 → 构建路径」的映射规则。

## 1. 模板（逐字给用户，或由访谈代填）

```markdown
# 报告诉求单
- 给谁看：（如：部门月度经营会 / 自用查数 / 汇报投影）
- 要回答的问题：（1–5 条业务问句，如「各产品族本月净流入如何」「哪些办事处库存异常」）
- 数据范围：（时间范围 / 组织范围 / 口径说明。**时间词要带锚点**：「本月 / 最新一期」以**数据最大期**为准（经营月报口径）；要按自然今天算请写明「自然今天」）
- 必须出现的指标：
- 对比方式：（环比 / 同比 / 目标 / 无）
- 必须出现的图：（可点名图表类型；不知道就空着）
- 不要出现的东西：（如：不要散点图、不要明细表、不要封面）
- 排版偏好：（页签 / 单页 / 主题色 / 页宽；也可贴一张草图或参考截图）
```

规则：**每一槽都有缺省（不填 = 数据形态推断），任何一槽都不强制**。填空永远
比自由写作容易——用户答不了的就留着，别追问到烦。

## 2. 槽位 → 请求词汇映射

| 槽位 | 落点（请求词汇见 authoring-feature-map.md） |
|---|---|
| 给谁看 | 详略与口径注释密度；汇报投影 → 建议开汇报模式核对 16:9 |
| 要回答的问题 | 每条问句 → 一张 chart（presetId 由问句动词选：趋势/对比/构成/转化/关联）|
| 数据范围 | `filters`（value 谓词直接过滤）或 `chart.table.dateScope/dimScopes` |
| 必须出现的指标 | `kpis`（≤4）；带窗口派生指标的对比见 derived.measures |
| 对比方式 | 无指标时 → 不落；有指标时 → 数据源配置建窗口派生指标 + `kpi.compareMeasure` |
| 必须出现的图 | 对应 chart 的 `presetId`/`encoding` 直接声明 |
| 不要出现的东西 | **排除项是实现自由的关键**：不要明细 → 不写 `dataTable`；不要 KPI 条 → free 档；不要某类图 → charts 里不声明 |
| 排版偏好 | `runtime.mode`（tabs/单页）、`style.chartTheme`、`pageWidth` |

## 3. 诉求单 → 构建路径（三档）

1. **只填「要回答的问题」** → 标准模板（`--patch`，suggest 默认 + 补丁覆盖）。
   快速看数的缺省路径。
2. **填了排除项 / 点名了图或版面** → 仍是标准模板，但补丁里显式覆盖
   （排除 = 不声明 + 必要时 `columnRoles.ignore`）。
3. **声明了完整结构取舍**（明确不要封面 / 不要 KPI 条 / 只要某几块）→
   `--free`（templateId=free-v1，声明即全部，无自动填充）。

判断启发：**用户在「要什么」之外还说了「不要什么」且成体系**（比如一张极简
查数页），才走 free；否则标准模板的自动填充是增益不是噪音。

## 4. 诉求单的落盘与生命周期

- 诉求单落盘为 `build/brief.md`（与 `build/decisions.md` 并列）。
- 它是诉求的**累积状态**，不是一次性问卷：月度刷新 / 迭代修改时增量改它，
  再按 §3 重新选路径构建。
- 用户对草案报告说的每句修改（「趋势换占比」「KPI 换毛利率」），除转成补丁外，
  同步回写诉求单对应槽位——下次刷新不丢。
- 与 decisions.md 的分工：brief.md 记**用户要什么**（需求侧），
  decisions.md 记**系统/作者各定了什么**（供给侧）。交付时把 decisions.md
  指给业务，把 brief.md 留给下一次刷新。
